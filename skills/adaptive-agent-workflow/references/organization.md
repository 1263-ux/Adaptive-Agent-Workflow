# Dynamic Organization

## Principle
Organize around work and outputs, not permanent Agent titles. There is no required Root → Lead → Worker → Reviewer hierarchy. The owner may execute directly, delegate or change the organization as evidence emerges.

## Delegate only for a reason
Delegate when an independent inspectable output exists and there is a real benefit: distinct expertise, parallel time savings, context isolation or independent evaluation. Do not delegate merely because a task is large or has many steps.

## Minimal task brief
For ordinary work, pass only:
- Goal
- Output
- Inputs
- Constraints
- Acceptance

Add dependencies, owner, write scope, baseline/version, budget and integration plan only when needed.

## Topologies
Direct, Sequential, Research-first, Probe-first, Parallel and Hybrid are all valid. Choose and change topology as the task evolves.

## Handoff
Preserve goal/current state, verified findings, decisions, completed artifact locations, blockers/risks, and next action/acceptance. Do not copy entire chat histories unless needed.

## Shared state
Before concurrent writes, use host-enforced isolation, separate worktrees/sandboxes, a single-writer policy or explicit file ownership. Prompt-only boundaries are not enforcement. Agree on interfaces before parallel implementation and integrate incrementally.

## Restructure and review
Split, merge, reassign, pause, resume or stop tasks as needed. Preserve useful work and mark superseded outputs. If nested delegation is unsupported, use flat dispatch. Review effort matches risk; independent review should inspect actual artifacts. A different session ID alone does not prove independence.
