# Operating Model

## Framework responsibilities
Understand goals, select work modes, discover/evaluate/assemble capabilities, organize responsibilities, preserve necessary task state and adapt from results.

It does not replace domain methodology, force multi-Agent execution, duplicate every Skill, replace host permission controls or measure productivity by process counts.

## Four conceptual planes
| Plane | Includes | Key question |
|---|---|---|
| Intent | Goal, success criteria, constraints | What outcome is needed? |
| Method & Capability | Methods, Skills, tools, resources | How can it be achieved? |
| Organization | Agents, responsibilities, tasks, dependencies | Who does what, and how? |
| Outcome & Learning | Artifacts, evidence, evaluation, experience | Did it work, and what changes next? |

These are conceptual boundaries, not separate services. Complexity is contextual: consider goal clarity, uncertainty, specialization, dependencies, shared state, write conflicts, risk, permissions, budget and integration cost. Choose the smallest organization that can satisfy the goal. Reuse project README, AGENTS.md, issues, host task records and version control as sources of truth; avoid duplicate Agent dossiers.
