# Dynamic Task and Team Organization

## No fixed roster
No mandatory Root/Lead/Worker/Reviewer hierarchy. Responsibility labels describe current accountability, not permanent Agent identity. An owner may execute directly.

## When to delegate
Delegate when a subtask has an independent inspectable output, needs distinct expertise, can run in parallel with net time benefit, benefits from context isolation or needs independent high-risk verification. Do not split without a clear output, input and integration path.

## Minimal task contract
Ordinary tasks: Goal, Output, Inputs, Constraints, Acceptance. Complex collaboration may add owner, dependencies, write scope, baseline/version, budget, integration plan and handoff.

## Task topologies
Direct, Sequential, Research-first, Probe-first, Parallel and Hybrid are all valid. Topology can change during execution.

## Team changes and resources
Allow split, merge, owner replacement, member reuse, fresh context, pause and termination. Handoffs preserve verified facts, artifact locations, current state and next action, not entire chat histories. Concurrency depends on task independence, host limits, budget and integration cost. Shared files require worktrees, sandboxes, locks or an explicit single writer; prompt-declared boundaries are not physical isolation.

## Independent review and host limits
Use independent review according to risk. The reviewer should not have participated in implementation and should inspect real artifacts in a separate context. Different session IDs alone do not prove independence. If nested delegation is unavailable, top-level dispatch can return results to the logical owner. Never invent host capabilities.
