# Dynamic Organization Playbook

## Principle
Organize around work and outputs, not permanent Agent titles. There is no required Root → Lead → Worker → Reviewer tree. The current owner may execute directly, delegate or change the organization as evidence emerges.

## Delegate only for a reason
Delegate when an independent inspectable output exists and there is a real benefit: distinct expertise, parallel time savings, context isolation or independent evaluation. Do not delegate merely because a task is large or has many steps.

## Minimal task brief
For ordinary tasks, pass only:
- Goal
- Output
- Inputs
- Constraints
- Acceptance

Add dependencies, owner, write scope, baseline/version, budget and integration plan only when needed.

## Valid topologies
Direct, Sequential, Research-first, Probe-first, Parallel and Hybrid are all valid. Choose and change topology as the task evolves.

## Ownership and handoff
A handoff should contain goal/current state, verified findings and decisions, completed outputs and exact locations, blockers/risks, and next action/acceptance. Do not copy entire chat histories unless needed.

## Shared state and integration
Before concurrent writes, use host-enforced workspace isolation, separate worktrees/sandboxes, a single-writer policy or explicit file ownership. Prompt-only boundaries are not enforcement. Agree on interfaces before parallel implementation when outputs depend on each other. Integrate incrementally.

## Restructure
The owner may split, merge, reassign, pause, resume or stop tasks. Preserve useful completed work and mark superseded outputs. If nested delegation is unsupported, use flat dispatch.

## Review
Review effort matches risk. For important or subjective results, use an independent evaluator where possible. A different session ID alone does not prove independence. Review actual artifacts, not self-reported completion.
